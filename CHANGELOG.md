# Changelog

All notable changes to RayTeX are documented here. The format follows [Keep a Changelog](https://keepachangelog.com), and versions follow [Semantic Versioning](https://semver.org).

## [Unreleased]

## [0.5.3] — 2026-10-15

- **Fewer passes, lighter passes.**
  - The build that completes a live one starts from where the live pass left the text, when nothing changed in between: that pass is not done again (one pass less each time the text is left alone on a long document, and before an export that follows a live build).
  - A document built for the first time, with a table of contents, labels, bookmarks or citations, has a first pass that writes no PDF and reads no picture: a second one comes for certain. With screenshots (pictures with transparency), such a pass takes a fifth of the time (1.3 s → 0.25 s for eight of them). A document that needs one pass is not made to wait.
  - A Biber or BibTeX run that fails is done again at the next build (its input was taken for done).
- A chapter compiled on its own works with latexmk too (it was compiled whole with it), and for a file brought in by `\import` (read from its own folder, as in the document).
- Fixed, a chapter compiled on its own started a page too early when the file before it ended on a page of text (`\input` one after the other): its page numbers were one less than in the document.
- **TikZ pictures drawn once.** After a build, each new TikZ or pgfplots picture is drawn in the background on a page of its own; the next builds put that page back in its place, to the pixel, with pdfLaTeX, XeLaTeX and LuaLaTeX (0.92 s → 0.54 s a pass for an article with a pgfplots curve and four drawings). A picture is drawn again when its text, a file it reads, the preamble, a definition of the document or what surrounds it (width, font, colour, language) changes; those that depend on the page or the rest of the document (references, counters, `remember picture`…) are always drawn. Exporting the PDF draws every picture. *Settings › Compilation › Keep TikZ pictures already drawn*.
- A smaller application: 14.0 MB instead of 17.0 MB on macOS. The code that reads, checks and draws while you work (the analysis of the text, the spell checker, images, compression) is still built for speed; the rest (the window, the network, the settings) for size.
- **A build no longer stops on a file of the build before.** When the engine cannot read an auxiliary file that an older build left (`.aux`, `.toc`…: written with a package removed since, or a line cut short), the error was shown as one of the document (« Missing \begin{document} », or a command unknown), with advice about the preamble, until the files of the build were cleaned by hand. These files are now put aside and the pass done again, once, from nothing. A wrong `.bbl` is still shown: its errors come from the document.
- **Precompiled preambles with MiKTeX too**: the preamble of a pdfLaTeX document is read once and kept, which makes each pass 35 to 55 % faster; it was kept for TeX Live. RayTeX now gives its own copy of `mylatexformat` (the file that writes such a preamble), so a basic MiKTeX does not have to download it, and a MiKTeX update of its packages makes the preamble be precompiled again.
- PDF viewer: a page keeps its size when the document gains or loses a page (documents with pages of other sizes no longer move at each build).
- **Pasting writes LaTeX.** Formatted text from Word, Google Docs, LibreOffice or a web page is pasted as LaTeX: bold, italic, underline, headings, lists (those of Word too, nested), links (`hyperref` added), superscripts and subscripts; a notice offers *Plain text* at once. Formulas come as formulas: MathML, the TeX a page carries with its formulas (Wikipedia), and the equations of Word (OMML: fractions, scripts, roots, sums and integrals with their limits, brackets, matrices, accents, functions). A table (Excel, Calc, Word, a page) opens in the table window; inside a formula, as a matrix. LaTeX code, plain text and code from an editor are pasted as they are.
- **Special characters escaped as they are typed**: `&`, `_`, `#` in text, and `%` after a number, are written `\&`, `\_`, `\#`, `\%`, never in a formula, a table or an alignment, the name of a label, a file or a link, a definition, a comment, the preamble, TikZ or code. One undo puts the character back; the first time, a notice says so, with a button to turn it off.
- **Shortcuts learned**: a command typed in full again and again (six times, letter by letter) gets one offer: the `@` shortcut of RayTeX that writes it, or a new one in a click. Never twice for a command, at most one offer in ten minutes.
- **Find and replace redone.** In the file, a card floats at the top right of the editor: <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>F</kbd> to find, <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>R</kbd> with its row of replacement; the matches are counted (*2 of 5*), with match case, whole word and regular expression, Enter for the next, Shift+Enter for the previous, Alt+Enter to select them all, Replace and All. In the project, <kbd>Ctrl</kbd>/<kbd>⌘</kbd> + <kbd>Shift</kbd> + <kbd>F</kbd> and <kbd>Shift</kbd> + <kbd>R</kbd> open the *Search* panel, redone: results by file with their folder and count, each line showing what it will become (struck out, then the new text), replaced alone, with its file, or all; whole words; `$1` of a regular expression. <kbd>Ctrl</kbd> + <kbd>R</kbd> no longer reaches the window when the focus is out of the editor (it reloaded it).
- These three aids are settings of the editor, on by default. A selection was already wrapped by `(`, `[`, `{` and `$`: it is now tested.

## [0.5.2] — 2026-10-14

- Fixed, the same problem shown two or three times with the same fix when the mouse is over it: a mistake is often seen by several checks, each with its fix (a citation key mistyped by LaTeX, by Biber and by the live checks; a brace never closed by the compiler and by the live syntax check; a missing image or file by both). Of the problems at the same place that offer a same fix, only the most serious is shown, in the text and in the *Problems* panel. Two places mended by a same fix (two commands of one package) are still two problems.
- Fixed, the `@{` and `@[` shortcuts (`\left\{ … \right\}`, `\left[ … \right]`): `@{` was never offered (a brace was not taken for the key of a shortcut), and the bracket the editor closes by itself is replaced with the shortcut. `@{` is offered in a formula or after a space, not in the `@{}` of the columns of a table.
- **Tables have their caption under them**: the table window, the table of the formatting bar, the `tab` snippet, the *Article* and *Lab report* templates and the help put `\caption` and `\label` after the `tabular`, as for a figure.

- **A chapter can be compiled on its own.** When a part of a document is opened (a file brought in by `\input`, `\include` or `\subfile`), RayTeX asks once per project what to compile while it is written: *This file only* or *The whole document*. The question is a small card under the **Build** button that takes no focus (typing goes on, and the whole document is compiled until it is answered); the choice is kept on this computer, nothing is written in the project, and it is changed in the menu of the **Build** button.
  - **This file only** compiles the file with the preamble of the document as it is written (its precompiled preamble serves): on a long document, a fraction of the time. The file stays what it is in the document: the numbers of its chapter, sections, figures and equations, its pages, its references to the other files, its citations (the same numbers with Biber), the commands defined in the other files, `\appendix` or `\mainmatter` met before it.
  - To know them, the whole document is compiled once in a folder of its own, LaTeX noting the value of every counter where each file starts (file hooks, LaTeX 2020 and later; without them, the file is shown with its own numbers). This record serves until another file changes. The PDF, the auxiliary files and the state of the whole document are not touched.
  - A line above the PDF says which file is shown alone, with a button back to the whole document. The main file shows the whole document again, the PDF follows the file when another one is opened, SyncTeX looks into the PDF on screen, and an export always compiles the whole document.
  - With pdfLaTeX, XeLaTeX and LuaLaTeX, our own driver (latexmk, Tectonic and steps of one's own compile what they are given: the whole document). Not for a file read by the preamble or brought in by `\import`.
- Sturdier reading of problems: a problem said to be on a line that does not hold what TeX quoted no longer stops the build (found while making the above).

- **Live builds of long documents take less time and less of the computer.** Measured first, on a document of 230 pages in 12 chapters (and the same in one file of 720 KB): a pass of the engine takes 2.9 s, a change that moves the pages that follow costs two passes (5.8 s), and the editor itself is not what is slow (2 ms a keystroke). So, for a document whose pass takes more than a second and a half:
  - **A live build is one pass.** The page shows what was typed after one pass (2.9 s where it took 5.8 s); what would complete it (references that moved, the table of contents, the bibliography, an index) is written down and done by a build of its own once the text is left alone a little longer. *Build*, an export and anything that needs the finished document make a whole build at once, and an export never takes a page whose references are still to settle.
  - **A build of an older text gives way.** Typing again during a live build used to let it run to its end, then start the next one: the engine finished a page nobody would look at. It is now stopped for the newer text, unless it was about to finish, and never more than twice in a row, so that the page keeps moving under steady typing. The auxiliary files of a pass that is stopped (by this, or by the user) are put back as they were: the next pass does not read half of the labels.
  - **A longer breath before a long build**: the pause waited for before a live build grows with the time a pass takes (up to 2.5 s), so that a build of several seconds does not start at each hesitation.
  - **The engine reads a long file less often**: it analysed the whole file a quarter of a second after each change; for a file of more than 200 KB it now waits up to 1.2 s of calm (completion and the other requests still send the text at once).
  - Short documents build as before.

- ***See all* redone**: the same tools, shown another way. It was five columns of small lines to read through. It is now a panel with a field at its top that finds a tool by its name as it is typed, without its accents (Enter runs the first one found, and `alpha` finds the `@a` shortcut); the families on the left (Text, Paragraphs and headings, Maths, Insert, Page, @ shortcuts) show one at a time, or everything; and each tool is a tile large enough to aim at, with the picture of what it does (the fraction, the root, the sum and the integral are drawn as formulas), its name and its keys. The sizes of the text are six letters of growing size, the colours a row of dots. Escape closes it and gives the cursor back to the text.

- **The images of a page style come into the project**: the image of a watermark, a logo in a header or a footer, and the logo of a title page were named where they were on the computer (`../../Pictures/logo.png`), so that a project moved or sent to someone lost them. An image chosen outside the project is now copied into its folder of images (the one it has, whatever its name, else `figures/`), under a name LaTeX accepts everywhere, and the copy is what the document names; a notice says where it went. An image of the project is named where it is.

- Fixed, the editor going back down to where the cursor was: after typing at the bottom of a text, going back up and clicking somewhere to write there, the letters could go to the old place and the view jumped down to it. The click had not placed the cursor, in two cases. On macOS, a click in the window while another application or another window was in front only brought RayTeX back to the front (the text under it can be scrolled without that, which hides it); the click now also places the cursor, as in other editors. And a click in the margin of the editor (the line numbers, the columns of the folds and of the problems) was ignored; it puts the cursor at the start of that line, and Shift extends the selection to it. A click in the text itself was followed in the application through a save and a live build: the cursor and the view stay where the click was.

- **The export of the PDF has a window of its own**: a real window of the system, apart from the main one (it can be moved to another screen, and the work goes on in the editor), in place of the small card of 0.5.1. It shows the export in detail:
  - its steps one after the other (each pass of the engine, the bibliography, the images made lighter, the writing of the file) with the time each took, and those still to come, known from the last build;
  - the file the compiler is reading (followed in its output, where it opens and closes each file) and the page it is at;
  - a progress bar with its percentage, an estimate of the time left and the time elapsed;
  - everything the compiler writes, as it writes it.
  - It closes by itself when the PDF is written, unless *Keep this window open at the end* is ticked; it then says where the PDF is and shows it in its folder. A build that ends with errors keeps it open, with the errors one click away in the main window. Opened in the middle of a build, it is told what that build did before.

- Fixed, TikZ studio: in a narrow window the note of the LaTeX rendering (*Up to date (1234 ms)*) went onto a second line and took its height from the rendering, which also moved by a few pixels each time a compilation ended. The bar keeps one height and shows the time alone (the sentence is its tooltip), and the rendering has a little more room.

- Fixed, code window: its preview was a whole sheet of paper with the code in small at its top, in a narrow column: nothing could be read. The page of the preview is cut to the code (set as wide as a line of the document, so that lines wrap where they will), and it is shown under the code, as wide as the code. A long code shows its first 40 lines. In a presentation the preview stays a slide.
- **Previews know the commands of the project wherever they are defined.** A preview (TikZ picture, trial of a command, sample of a font, code, title page, page layout) was built with the preamble of the main file: a command defined after `\begin{document}`, or at the top of a chapter, was unknown to it, and the picture that used it showed an error where the document compiled. These definitions are now given to every preview, each written so that it cannot break one: it is run only when the command that defines exists (`\DeclareMathOperator` needs amsmath), and when what it defines is not there yet (a file the preamble reads may have defined it), or, for a `\renewcommand`, already is. The formulas in the texts of the whiteboard use the commands of the project too, like the formulas of the document.

## [0.5.1] — 2026-10-12

- **Code in the document** (*Insert code…* in *See all* and the command palette): a window with the code on the left and, on the right, its settings and the listing compiled by LaTeX. It writes the `listings` package, which works with every engine and every distribution and asks for no outside tool.
  - **The language**, among about forty. Those `listings` does not know (JavaScript, TypeScript, Rust, Go, Kotlin, Swift, Dart, Julia, JSON, YAML, TOML, CSS) come with their definition, written in the preamble when they are used.
  - **The indentation**: *2 spaces*, *4 spaces* or *Tabs* writes the code again level by level (an alignment keeps its spaces). Code pasted from the middle of a file comes back to the margin; tabs and spaces that are mixed are pointed out.
  - **One style for the whole document**: *Light*, *Plain* (black and white, for print) or *Dark*, line numbers, line wrapping, a frame, the size of the text. It is one block of the preamble, written once and read back; a block changed by hand is kept unless another style is chosen.
  - **Helps for a good display**: LaTeX measures how many characters a line of the document holds, and the window says how many lines are too long, with line wrapping or a smaller text one click away; accented letters (a comment in French) work with pdfLaTeX too; in a beamer presentation the frame gets the `fragile` option code needs.
  - A caption and its label; behind *Advanced*, the width of a tab, code read from a file of the project (`\lstinputlisting`) and other options for one listing. The **Code** chip after `\begin{lstlisting}` opens the window again on that code. With text selected, *Insert code…* starts from it.
  - Checked with the real engines: every theme and every language compiles with pdfLaTeX, XeLaTeX and LuaLaTeX (which found two definitions to correct before anyone met them).
- **A lighter PDF** (*Export PDF…*, when the document has PNG or JPEG images): a small window asks how the PDF is wanted, and says about what each choice would weigh before anything is done: *Images as they are*, *Lighter images* (2400 pixels wide at most: nothing shows, printed too), *Light images* (1600 pixels: fine on a screen), or *No more than* a size in megabytes.
  - **Neither the images nor the project are touched.** The document is built once more, apart, in a copy of the project kept in the cache, with lighter copies of the images it embeds and the state of its last build (one pass is enough); the copy is removed when the PDF is written. The window of the export follows it: the images made lighter, then the compiler.
  - **Under a size**: RayTeX picks the gentlest of eight steps of compression that should do, weighs the PDF it gets, and goes a step further while it is over (three times at most); a limit that cannot be met is said, with the weight that was reached.
  - A photograph kept as a PNG is embedded as a JPEG without a word of the document changing: the engines tell an image by what it holds, not by its extension (checked with pdfLaTeX, XeLaTeX and LuaLaTeX). Drawings, screenshots and images with transparency stay PNG, without loss; PDF and EPS figures are not touched. Measured in the application: a PDF of 6.9 MB with one photograph, 1.0 MB with light images.
  - The lighter copies are kept for two weeks, so that the estimate and the export that follows share their work.
- **Images, several at once**: the images inserted together are one thing in the code too.
  - **One chip for the group**: a figure of sub-figures, or images side by side, had a chip on each image, which opened the window on that image alone. They have one, *2 images*, and a click opens the window on all of them: their order, the caption of each, the images per row, the caption and the label of the figure. *Update* writes the figure again, with what the document already wrote for each image kept as it is (its path, its label). A figure with anything else in it is left to its images one by one, as before.
  - **Their order is changed by dragging** each image by its handle (or with the up and down arrows), and the sketch of the page shows every image at its place.
- **Lighter images** (*Weight of the images* in the image window: *Original*, *Lighter*, *Light*): what is copied into the project is a lighter copy, and each image says what it weighs and what it will weigh before anything is written. A photograph is made smaller (2400 or 1600 pixels wide at most) and written as a JPEG, even when it came as a PNG (a pasted photograph of 4.2 MB: 0.3 MB); a drawing, a screenshot or an image with transparency stays a PNG, without loss; PDF, EPS and SVG are not touched. The colour profile is kept, a copy that would not be lighter is not made, the image that was chosen is never changed, and the choice is kept from one time to the next.
- **Exporting the PDF while the document compiles no longer writes a broken file.** The PDF was copied at once, even while the engine was writing it: the copy had a start and no end, and no reader opened it. The engine now refuses to copy the PDF a build is writing, or one that has no end, and a copy is written whole or not at all.
  - ***Export PDF…* compiles first when it has to** (the document changed since its last build, or a build is running), and a small window over the rest follows that build: the step of the compiler, the page it is at, a progress bar, an estimate of the time left (measured on the last build of the document; the time elapsed when there is none to compare with) and the last line the compiler wrote. It closes when the PDF is written. Closed before, the export goes on and says when it is done; *Cancel* gives it up.
  - A build that ends with errors exports nothing by itself: the window says how many, shows them, or exports the PDF as it is on request. A PDF that is up to date is exported at once, without a build.
- Fixed, TikZ studio: in a window that is not tall (a laptop screen, a window that is not maximized), the tools were squeezed and ran over the bottom bar, and the settings on the right were cut by the rendering. Version 0.5.0 added two tools, and their column no longer fitted even in the window RayTeX opens with. The tools take two columns when one does not fit (smaller buttons in a very low window), the settings of a shape keep the room they need when the window has it, the LaTeX rendering never goes under a fair size (the settings scroll first), and the bottom bar and the shelf of the sets hold in a narrow window.

## [0.5.0] — 2026-10-11

- **A spell checker of its own, in the language of the document**: the words the dictionary does not know are underlined in the prose, the same way on macOS, Windows and Linux (the checker of the system, which was given the language of the interface and every command of a LaTeX file to spell, is no longer used).
  - **A dictionary is downloaded once, and only when you agree to it.** RayTeX ships none. Turning the checker on for a language it does not have opens a window that says what is downloaded (the dictionary of that language, its size), from where (`github.com/LibreOffice/dictionaries`, at a fixed commit) and that nothing else is downloaded or sent: *Download* or *Not now*. The checker then works without a connection. Twenty-one dictionaries are offered; *Settings › Editor* lists those installed and removes them.
  - **The language** is read from what the document gives to babel (the last language, or `main=`), to polyglossia, or from a `% !TEX spellcheck` line; it is shown at the bottom of the window, where another one can be chosen for the project. Passages in another language (`\foreignlanguage`, `otherlanguage`, `\textenglish{…}`) are checked with their own dictionary when it is installed.
  - **Only prose is checked**: commands, formulas, labels, keys and file names, the preamble but for its title, TikZ pictures and listings are left out, and so are acronyms, names with a capital inside and what touches a digit.
  - **A right click on an underlined word** offers the corrections of the dictionary and adds the word to yours (a proper name, a term of your field), right in every language from then on.
  - Checked with the real French, American English and German dictionaries (downloaded, read in a few hundredths of a second, elisions and hyphens understood: `l'équation`, `aujourd'hui`, `peut-être`). The engine is `spellbook` (MPL-2.0), which reads the Hunspell format.
- **Reporting a problem from the application** (*Report a problem…* in the command palette, and *Settings › About*): a report to paste in an issue, with the version of RayTeX and of the system, the TeX distribution, how the document is built and the errors of the last build. Nothing is sent: the report is shown whole, copied by the user and pasted where they choose; *Copy and open GitHub* opens the page of a new issue. The folder of the project and the name of the user are taken out of every path; the end of the build output, which may quote the document, is added only when asked.
- **Whiteboard (TikZ studio), four additions**:
  - **Links that follow the texts**: with the link tool (K), a drag from one text to another joins them with an arrow, drawn from border to border, which follows them when they are moved. It is written the way TikZ wants it: each linked text gets a name (`n1`, `n2`…) and the link is `\draw[->] (n1) -- (n2);`. A selected link is straight or bent to one side, and can carry a text; deleting a text deletes its links; copies and sets get names of their own. Such lines written by hand are read back as links.
  - **Alignment guides**: what is moved snaps to the sides and the middle of the other shapes when it comes close, and a line shows what it is aligned with (not with Ctrl or ⌘ held).
  - **A curve tool** (B): a smooth curve through the points clicked, open or closed, written as `plot[smooth] coordinates {…}`. The board draws it with the construction of TikZ itself, checked against the curve LaTeX draws; *Advanced* turns a broken line into a curve and back.
  - **Sets as a file**: *Export* writes the sets in a file to give to someone else or to take to another computer, *Import* adds those of such a file (no set twice, a taken name gets a number).
- **Exporting the project** (*Export the project…* in the project menu and the command palette): a `.zip` archive, whose content is listed before anything is written.
  - **The whole project**: all its files without the folder of the build, auxiliary files and hidden files; the PDF on request.
  - **For arXiv or a journal**: only what the document uses, with its compiled bibliography (`.bbl`) under the name of the main file. Comments are removed unless told otherwise (verbatim text and the `%` of addresses are left alone), the `.bib` files are added, and *Advanced* writes everything in one `.tex` file or adds the PDF.
  - What a document uses is not guessed from its text: every build now records the files the engine reads (`-recorder`, a `.fls` file in the folder of the build), and the export keeps those of the project. A document that was never compiled is compiled first; files changed since the last build are pointed out. Checked with a real build: the archive, unpacked alone, compiles with its citations resolved.
- **A title page studio** (*See all › Page › Title page…*, or the command palette): the title page written from a few fields, with the page compiled next to them with the class and the preamble of the project.
  - **Four layouts** chosen by their picture: *Classic* (`\maketitle`), *Centered*, *Report* (the institution at the top, the authors on the left and the supervisors on the right) and *Modern* (aligned on the left along a rule). Title, subtitle, authors and date in sight; the institution, the department, the kind of document, the supervisors and a logo in their group; the width of the logo, the words above the supervisors and the colour of the rules behind *Advanced*.
  - It is written in the main file in place of the title the document had (`\maketitle`, or a title page written before), with the packages it needs, as one change that can be undone. The code is plain LaTeX in a `titlepage` environment, each line saying what it is in a comment (`% title`, `% author`): it can be touched up by hand, and the window opened again finds its fields. `&`, `%`, `#` and `_` are escaped; commands are kept as typed.
  - With beamer, the window sets `\title`, `\subtitle`, `\author`, `\institute` and `\date`, and the title frame.
- **A local history of the project**: RayTeX keeps *moments* of its source files (`.tex`, `.bib`, `.sty`, `.cls`…), to compare and to go back. *Project history* (the project menu, the command palette, or *History of the file* under the right button in the files) shows the moments by day and, for the one chosen, what changed since: file by file, line by line, the words that differ marked in a line that was rewritten.
  - **Restore this file** gives a file back the content it had, **Restore everything** all of those that changed. The project as it is now is kept as a moment first, and a file is put back through its document: going back can itself be undone.
  - **Light by default**: a moment when the project opens, then at most one every 10 minutes while it is saved, and none when nothing changed; a content is kept once however many moments have it; pictures, PDFs and the files of the build are left out. Old moments thin out (all of the last day, one per hour for a week, one per day up to 30 days). Nothing is written in the project folder, and nothing leaves the computer.
  - *Settings › Editor › Local history*: the time between two moments, how long they are kept, or no history at all. *Keep this moment* takes one at once; the menu of the window clears the history of the project.
- **A PDF of the changes** (in the history, for the moment chosen): the document compiled with what changed since then, removed text struck out and added text underlined, the files it includes folded in. It is made by `latexdiff`, the program of the LaTeX distributions for this, and compiled like the project (same engine, same bibliography tool); it is shown in the window and saved where you say. Nothing of it stays in the project: the document latexdiff writes is next to the main file for the time of its build only, and it is built in a folder of its own. A distribution without latexdiff is told so, with its installation one click away; a document of changes that does not compile says what stopped it, and the comparison line by line is still there.
- Fixed, export for arXiv or a journal: on Windows, the archive could hold the bibliography and nothing else. The engine records the files it read under the name the folder was given, and the same folder can be named two ways (a short name such as `C:\Users\RUNNER~1` for `C:\Users\runneradmin`, or a link): the files of the project were not seen as its own. Paths are compared as the system itself names them. Found by the scenes of the application on Windows.
- For contributors, MiKTeX, second run of 11 October: the application passes all its scenes on a real MiKTeX, the margins window included (why its measure was missing in two earlier runs is not established: the engine test added for it passed in both). `ulem.sty` was fetched by MiKTeX itself this time. The one failure left is MiKTeX's own: `miktex packages install babel-icelandic` ended with "Sorry, but: Timeout was reached", for a package it installed in every other run. The tests run such a step again, and the help says what that message means.
- For contributors, MiKTeX, after the run of 11 October on a real MiKTeX: the engine reads the fourteen lengths of the margins window there (the new test passes), so what the scene of the application waits for is elsewhere, and its job did not run that day (MiKTeX itself failed to install on the runner, three times). One at a time, the cases of the common mistakes no longer meet the font map cut short; one still fails: MiKTeX, its installer on, does not fetch `ulem.sty`, in a run where it fetched every other package.   - A key is looked for as a whole word (`widt` in `widt=\linewidth` was replaced inside `\linewidth`), and compared with the names of the keys, not with `key=value` (`versionn=4` became `version=4=4`).
  - An error of beamer inside a fragile frame is shown in the document, not in the file beamer writes for it.
  - The search for a cause cannot make a build fail any more: a fault in it leaves the problem as TeX gave it.
- **Warnings are placed on their cause, like errors**:
  - A letter with an accent, a character of text (`°`, `€`, `œ`) or an accent of text (`\'e`) in a formula: LaTeX only says "Command `\'` invalid in math mode" for the whole line, and the letter is missing from the PDF. The word is now shown, the problem says what it is, and a fix writes it in `\text{…}` (or as `\acute{e}`, `^\circ`). Without T1 fonts the same mistake is an error, explained the same way. The "Missing character" line TeX adds for it is no longer listed apart.
  - A command the warning names is shown where it is written (`\over` with amsmath, `\Large` in a formula, `\circle` in `picture`), and a name it quotes is looked for in the whole statement, not only on its last line.
  - A level of titles that is skipped (`\subsubsection` right after `\section`, reported by hyperref), an option of `\documentclass` nobody uses (with the closest one that exists), a `\maketitle` without author.
  - A character of an 8-bit font is no longer lost when the log is read ("There is no É in font cmr10").
- The fix of `$$ … $$` changes both ends at once: it replaced the closing `$$` only, which left the formula open. Two formulas that follow each other (`$a$$b$`) are no longer taken for a `$$`. `$$`, `eqnarray`, old packages and `inputenc` with XeLaTeX or LuaLaTeX each get their own explanation, instead of one about "this command".
- The cross that closes a tab is in the middle of its square.
- A lighter application: the fonts of the formula previews ship in one format (WOFF2) instead of three, about 0.8 MB less in the interface.
- For contributors: the tests of every push run with TeX Live, on Linux and on Windows. MiKTeX stays supported like before; its tests (the same ones, with packages installed on the fly) moved to a workflow run on demand (*Actions › MiKTeX*), because a failure of its download servers failed them.
- For contributors: `npm run app:dev` and `npm run app:build` find cargo when it is not on the PATH (an IDE started from the Dock, rustup from Homebrew) instead of stopping on "failed to run 'cargo metadata'".
- For contributors: the tools that made the pictures are gone from the repository (the scripts of the logo, the page of the sharing picture, `scripts/screenshots.mjs` and its scenes); the pictures stay. Icons that no installer used and two unused dependencies are removed.

## [0.1.0] — 2026-10-01

First version.

### Errors and fixes
- Every error and warning gets a suggestion (a catalogue of about 110 LaTeX, package, BibTeX and Biber messages, in French and English, plus an explanation for the others) and, for the common ones, a fix computed from the sources: misspelt commands, environments, labels, citation keys and option keys; missing packages and TikZ libraries; unclosed braces, formulas and environments; `_`, `^`, `&`, `#` in text; table columns and rows; float placement and oversized images; `\newcommand` arguments; misplaced `\usepackage`; option clashes; babel, fancyhdr, pgfplots, natbib and hyperref warnings; cleveref with French babel.
- **Fix all** in the Problems panel (first suggested fix of each problem shown, duplicates and conflicting edits skipped, then a build) and **Alt+Enter** in the editor for the fixes at the cursor. Diagnostics and fixes follow the edits made since the build.
- Errors reported inside a package (`geometry.sty:1005`) are moved to the `\usepackage` line and option that cause them.
- Tested with the local TeX distribution on about 110 documents made of common commands and common mistakes: each one is reported, explained and fixed, and a document using the most common commands and environments compiles without any warning (`crates/raytex-core/tests/common_mistakes.rs`).
- The application is now called **RayTeX**, with a new logo (a manta ray — the *Ray* — gliding with the \\TeX logo typeset by LaTeX); the command line is `raytex`. The folders and files of the versions named LaBagueTex follow on first start: projects folder (`Documents/RayTeX`), settings, session and cache, and each project's `labaguetex.toml` (renamed `raytex.toml` when the project opens).

### Windows
- The repository can be checked out on Windows: the module `aux.rs` (AUX is a name Windows reserves) is now `auxfile.rs`, and the CI checks that every file name is valid on Windows; line endings are kept by `.gitattributes`.
- Characters typed with AltGr (Ctrl + Alt for the page: `{ [ @ \\ €` on AZERTY) are never taken for Ctrl + Alt shortcuts.
- A file opened from Explorer while RayTeX runs goes to the running window (single instance, Windows and Linux).
- MiKTeX's own window asking to install each missing file never appears: every engine run tells MiKTeX what to do. Builds and the previews of formulas, TikZ and fonts install missing packages silently when *Install missing packages automatically* is on (the default); template thumbnails never install anything. When MiKTeX cannot install by itself (setting off, TeX Live), RayTeX lists the packages a document loads but the distribution lacks, in one notice with an **Install** button; the installed files are read again after MiKTeX installed some.
- MiKTeX is named after its version (`MiKTeX 25.12`, not the version of pdfTeX); TeX Live's `tlmgr.bat` is found; package documentation falls back on `mthelp`; a missing Biber comes with an Install button; an engine that stops without writing its log (a distribution to finish setting up or to update) shows its own message.
- The title bar is part of RayTeX's top bar: on Windows the system bar is gone and RayTeX draws the minimize, maximize and close buttons (still usable over dialogs); the empty parts of the bar move the window and a double click maximizes it. On macOS the close, minimize and zoom buttons sit in the top bar. The window state no longer brings back the system bar.
- Projects in folders whose path has a space, an accent or a Windows short name (`C:\Users\Jean Dupont\…`, `RUNNER~1`) build with MiKTeX: the engine runs without `TEXINPUTS`, which made MiKTeX rewrite the root file as a full path that TeX misread. Paths no longer carry the `\\?\` prefix of Windows. The *modern article* template loads its Libertinus fonts by file name, which MiKTeX finds.
- A click on an error (or in the PDF) no longer opens a second, read-only copy of a file of the project: when TeX or SyncTeX writes its path otherwise (another case, other slashes, a Windows short name, through a link), it is named like the project names it; on Windows, paths are compared without regard to case.
- `npm test` works from Node 22.12 (Node 23.5 needed an option to run TypeScript).
- MiKTeX is named with its version from the first start after its installation (its reminders came before the version line, and its first run can be slow; its own tools are asked too).
- Quitting RayTeX stops the TeX runs still going (builds and previews, never installations), so that none goes on alone holding files open.
- When MiKTeX stops a compilation by itself (a package it cannot download, a damaged format…), the problem gives the reason MiKTeX wrote in its own log instead of the path of that log.
- `\usepackage[francais]{babel}` (and `frenchb`, `germanb`, `ngermanb`, `portuges`, `brazil`, `magyar`…) gets its fix with recent babel too, which no longer knows these names at all ("Unknown option"): the old name is replaced by the current one.
- Deleting several files: the confirmation says the files (plural) can be restored from the trash.
- Releases ready to be signed (docs/SIGNING.md): Windows installers by SignPath (free for open-source projects) and macOS builds by Apple (Developer ID and notarization), each turned on by its secrets; every release gets `SHA256SUMS.txt` and a build provenance attestation (`gh attestation verify FILE --repo ifanoxy/raytex`). The download page explains how to verify a file.
- A website, in English and French, published on GitHub Pages (`site/`): landing page with a live demo of an error explained and fixed, features, downloads (the system and the processor are detected, any other is one click away, every published version stays available, files hosted in the GitHub releases, with their SHA-256), versions with their notes, getting started guide, FAQ, about and contributing, legal notice, privacy policy and license; light and dark themes, no cookie and no tracker.
- Ready to be published as open source: README with screenshots (English and French), code of conduct, security policy, issue and pull request templates, notices of the third-party components (`THIRD_PARTY.md`), how to release a version (`CONTRIBUTING.md`); links point to the GitHub repository.
- The thumbnails of the built-in templates are shipped with the application (first pages as images, 600 KB in all): the gallery shows at once (1 ms instead of 5 s of compilation) and with any distribution, MiKTeX without the templates' packages included. User templates are still compiled once and kept in the cache. `RAYTEX_WRITE_THUMBNAILS=1 cargo test -p raytex-core --release -- --ignored write_bundled_thumbnails` refreshes them; a test fails when a template changed without it.
- Saving a file while another program reads it (TeX during a build, an antivirus, the search indexer) no longer fails with "Access is denied": the save tries again for a moment, then writes the file in place; no temporary file is left in the folder. Two saves of the same file at once (the editor's and the one before a build) no longer fail with "cannot find the file specified": they come one after the other, each with its own temporary file.
- The TikZ studio no longer undoes a first stroke or tab chosen right after opening it (the gallery and the libraries arrived later and reset the board), and pasting an SVG reads the system fonts once and only when the drawing has text (seconds on Windows).
- "auto expansion is only possible with scalable fonts" (microtype with a font installed only as a bitmap, or whose MiKTeX package is still being installed) is explained: build again, install the font's `-type1` package, or `expansion=false`.
- Images pasted and inserted right after the image dialog opened go into the project's folder (they could be written next to the application, then refused as outside the project).
- Choosing a LaTeX font that is not installed no longer warns when MiKTeX installs packages by itself: it comes with the next build.
- A preview (TikZ, font) that produces no PDF always says why: time limit reached (MiKTeX may still be installing a package: try again), or the engine's last message.
- The window is brought inside its screen at start when it is larger (first start on a laptop: 1366 × 768, or 1920 × 1080 at 150 %), so the status bar is not under the task bar.
- The format bar fits at every window width from 900 px: its breakpoints were measured again with the Matrix button (alignment and links hide below 1510 px, texts below 1195 px, undo/redo and macros below 980 px).
- Check boxes, radio buttons and sliders take RayTeX's colour everywhere.
- End-to-end checks of the application in the repository: `node scripts/e2e.mjs` runs the self-test scenes (workflow, fixes, files, projects) on `tests/e2e/rapport` with a screenshot at each step, on macOS and Windows; the CI runs them on Windows with MiKTeX and builds the Windows installers (MSI, NSIS), both attached to the run.
- CI: integration tests (TeX Live, MiKTeX) in their own workflow, never cancelled by a newer push (the newest waits), so the long MiKTeX run always finishes.
- CI: integration tests with MiKTeX on Windows (packages installed on the fly), next to TeX Live on Linux; [docs/WINDOWS.md](docs/WINDOWS.md) explains how to build, test and check MiKTeX on Windows.

### Writing and layout
- **Completion of keys and values in arguments**: `\includegraphics[…]`, `\begin{itemize}[…]` (enumitem), `\hypersetup{…}`, `\geometry{…}`, `\captionsetup{…}`, `\sisetup{…}` and the siunitx commands, `\lstset{…}` / `lstlisting`, `minted`, `tcolorbox`, `\setmainfont{…}[…]` (fontspec), TikZ (`tikzpicture`, `\draw`, `\node`…), pgfplots (`axis`, `\addplot`), `\printbibliography`, beamer's `frame`, `\includepdf`, `\todo`, `minipage` / `\makebox` / `tabular` positions, `\newcommand` arguments, `\vspace` and `\setlength` lengths; options of `\usepackage[…]{geometry | hyperref | caption | siunitx | biblatex}`. About 520 keys documented in French and English (`data/keys.json`), shown next to each key and in the documentation panel with their values; after `key=`, the values of the key (`label=\arabic*.`, `linkcolor=blue`, `legend pos=north west`…). The keys that the installed version of a package declares in its sources (`\define@key`, `\lst@Key`, l3keys, pgfkeys) are offered too, after the documented ones.
- **Hints for free arguments**: in an argument without proposals (`\item[…]`, `\section{…}`, `\caption{…}`, `\frac{…}{…}`, `\footnote{…}`, a command of the project…), a hint above the cursor shows the signature with the current argument highlighted (`\item[terme]`) and what to write there ("terme — free text shown instead of the bullet or number…"). About 90 argument names and 90 command arguments are described in French and English (`data/arguments.json`). Names of what to write (`[${1:term}]`) are no longer inserted as text: the field starts empty and the hint says it.
- Completion opens when the cursor is put into an empty argument (`\begin{|}`, `\ref{|}`, `\includegraphics[|]`, after `, `), and works when typing inside braces that are already closed (`\begin{e|}` showed nothing).
- **Grid editor** for matrices and tables (buttons *Matrix* and *Table* of the format bar: choose the size, then fill the cells). Enter goes to the next cell (Shift+Enter back), Tab in the last cell adds a row, arrows move between cells, Ctrl/⌘+Enter inserts; cells pasted from a spreadsheet (or LaTeX `&` / `\\`) fill the grid. Matrices: delimiters `( ) [ ] { } | | ‖ ‖`, none or small, with a live preview; inserted in `\[ … \]` outside a formula, amsmath added. Tables: alignment of each column, booktabs, grid or no rules, header row, optional floating table with caption and label; booktabs added.
- Each cell of the grid editor is a small LaTeX editor: colours, completion (commands, labels, citations, `@` shortcuts), macros (trigger + Tab, shortcuts), Ctrl/⌘+B, I, U, E and Ctrl/⌘+Shift+M, `$…$` pairs. An `&` typed in a cell is the character (`\&` in the code); the `&` of an environment inside a cell (`cases`) stay as they are. Spreadsheet values get `%`, `#`, `_` escaped. Tables have a live preview too (formulas, bold, italics, rules, `\multicolumn`), and both previews use the macros of the document. Escape inside a cell closes the completion or the snippet field, not the window.
- Chips also after `\includegraphics{…}` (the image dialog opens on that picture: file, width, placement, caption, label; Update rewrites it, a figure holding other material is edited command only, options other than a width are kept) and after `\begin{tikzpicture}` (the TikZ studio opens on it).

- The editor shows the characters as typed: `->`, `=>`, `<--` are no longer drawn as arrows.
- Symbols clicked one after another go into the same formula (`$\theta\xi$`), the cursor staying after it; the symbols panel inserts the backslash of the command (it wrote `$theta$`).
- Several files selected in the project tree (Shift + click for a range, Ctrl / ⌘ + click to add or remove, Shift + arrows, Ctrl / ⌘ + A), dragged into a folder or the text, opened, inserted or moved to the trash together (one confirmation).
- Files opened from the Finder (double click, *Open with*, dropped on the icon) or passed on the command line: a `.tex` opens in light mode, or in its project when it belongs to one; at start-up it takes the place of the last session. Quitting with ⌘Q asks about unsaved files like closing the window. The macOS bundle is signed ad hoc (it opens on another Mac instead of being reported as damaged).
- Formatting bar: a narrower font box, and the texts of **Image**, **Table** and **Diagram** stay visible (alignment and link buttons go first when the window is narrow).
- Projects folder (`Documents/RayTeX` by default, set in the settings) where new projects go; the start screen and a **My projects** window list them with a preview of their PDF, search, order, rename and trash, plus recent projects and files.
- Light mode: a `.tex` file opened on its own is edited and built without creating anything next to it (builds in the cache, PDF exported where you like); features that need a folder offer to make a project (name and place), copying the file and what it uses.
- Fonts from the formatting bar: a font box showing the document's font and a **Document fonts** menu (main, sans-serif, code, maths — change or reset each), fonts for passages applied to the selection (`\newfontfamily\fontName`), a clearer role chooser in the font window.

### Images, drawings and fonts
- *Insert images* dialog: files, clipboard, drag and drop or project images; folder and safe names; width, placement, caption, label; sub-figures; SVG → vector PDF, WebP/GIF/HEIC/BMP/TIFF → PNG.

### Engine
- Detection of TeX Live, MacTeX, TinyTeX, MiKTeX, Tectonic, system TeX Live and custom folders; index of every installed file.
- Analysis of any package or class source (commands, environments, options) for completion; bilingual knowledge base for common packages; CTAN catalogue.
- Guided installation of distributions and packages (tlmgr, MiKTeX, system package managers), in user mode when possible.
- Smart build driver (engine choice, bibliography / index / glossary tools only when needed, reruns until stable), latexmk, single pass and custom steps.
- Log parsers for TeX, BibTeX and Biber with exact positions, explanations and fixes; lint while typing.
- Native SyncTeX, navigation (definition, references, rename), word count, 16 templates in English and French.
- `raytex` command-line tool.

### Application
- Editor with context-aware completion, live math preview, hovers, snippets, macros, folding, multiple cursors, Vim mode.
- PDF viewer with SyncTeX, problems / output / installations panels, command palette, project search, outline, packages browser, help centre, settings, setup assistant, light and dark themes, English and French interface.
